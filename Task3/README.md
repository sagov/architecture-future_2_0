# Роадмап изменений

### Этап 1. Стабилизация и безопасность 

**Цель:** устранить Must Have-риски — угрозу лицензиям и непрерывности бизнеса.

| Действие | Результат для бизнеса |
|---|---|
| Развернуть облачную инфраструктуру (Kubernetes, VPC, шифрование) | Готовый фундамент. Безопасный контур для мед. и фин. данных. |
| Мигрировать операционные медданные в Aurora PostgreSQL | Медкарты изолированы от аналитики. Врачи не конкурируют с отчётами. |
| Внедрить API Gateway (Kong) | Единая точка входа. Аудит всех запросов к данным. |
| Настроить OAuth 2.0 + SSO | Безопасный доступ. Row-level security на уровне Gateway. |

---

### Этап 2. Доменные фундаменты 

**Цель:** реализовать Should Have — независимость доменов и self-service аналитику.

| Действие | Результат для бизнеса |
|---|---|
| Развернуть Kafka как единую шину событий | ИИ получает снимки мгновенно. Финтех и клиники обмениваются событиями асинхронно. |
| Развернуть Greenplum для финтех-домена | Финтех-команда владеет своим DWH. Запуск продуктов — без оглядки на клиники. |
| Внедрить каталог данных (Apache Atlas) | Бизнес-пользователи видят все доступные датасеты. Партнёры получают доступ только к разрешённым API. |
| Запустить портал самообслуживания (MVP) | Первый self-service отчёт строится за секунды, а не часы. |

---

### Этап 3. Продукты данных и партнёры 

**Цель:** полный Data Mesh, подключение партнёров, вывод легаси.

| Действие | Результат для бизнеса |
|---|---|
| Внедрить dbt во всех доменах | Трансформации как код. Воспроизводимость, CI/CD. Никаких хранимых процедур. |
| Опубликовать продукты данных всех доменов в каталоге | Единый реестр API. Аналитика по всем направлениям в одном портале. |
| Развернуть ClickHouse для кросс-доменной аналитики | Сложные отчёты по медицине + финансам — за секунды. |
| Подключить первого партнёра (фармкомпанию) через партнёрскую витрину | Партнёр получает обезличенную статистику. Core-системы не затронуты. |
| Вывести из эксплуатации SQL Server 2008, PowerBuilder, Apache Camel | Полный отказ от легаси. Снижение затрат на поддержку. |

# Бизнес-обоснование

- **Скорость принятия решений:** первый self-service отчёт в клиниках строится за секунды, а не часы. Управленческие решения ускоряются.
- **Качество сервиса:** интерфейс врача перестаёт «тормозить» из-за аналитических запросов. Приём пациентов ускоряется. Data Contracts гарантируют, что обновление продукта данных в одном домене не сломает отчёты в другом.
  ИИ-подсказки приходят мгновенно — качество диагностики растёт. Финтех-сервисы стабильнее — свои ресурсы, нет конкуренции с клиниками.
- **Снижение затрат:** отказ от поддержки on-premise ЦОД в пользу облака. Экономия на администрировании железа. Снижается нагрузка на IT-команду — пользователи сами строят отчёты. Полный отказ от легаси (SQL Server 2008, PowerBuilder, Apache Camel) — экономия на лицензиях и поддержке.
- **Масштабирование:** облачная платформа готова к добавлению новых доменов и партнёров без закупки оборудования. Новый партнёр подключается за дни, а не месяцы. Новый бизнес-домен (фармацевтика, электроника) создаётся по шаблону.


## Доменные команды (по одной на домен, кросс-функциональные)

| Домен | Состав | Ключевая ответственность |
|---|---|---|
| **Клинический** | Tech Lead, Backend (3), Data Engineers (2), DBA (1), QA (1) | Миграция на Aurora, медкарты, партнёрские витрины |
| **Финтех** | Tech Lead, Backend Golang/Java (3), Data Engineers (2), DBA (1), QA (1) | Greenplum, отчётность ЦБ, независимый CI/CD |
| **ИИ-сервисы** | ML Architect, Data Scientists (2), ML Engineers (2), Data Engineer (1), QA (1) | Модели, MLOps, real-time обработка снимков |
| **Аналитика** | Tech Lead, Frontend React (2), Backend (2), Data Engineers (2), UX (1), QA (1) | Портал самообслуживания, ClickHouse, каталог данных |

## Централизованные команды

| Команда | Состав | Ключевая ответственность |
|---|---|---|
| **Cloud Infrastructure** | Cloud Architect, DevOps (3), SRE (1) | Kubernetes, VPC, георезервирование, Terraform, мониторинг |
| **Security** | ИБ-архитектор, ИБ-инженеры (2), Compliance (1) | Шифрование, аудит, OAuth/SSO, ФЗ-152, требования ЦБ |
| **Platform Engineering** | Platform Architect, Engineers (3), SRE (1) | Kong, Kafka, Atlas, CI/CD-пайплайны для доменов |
| **Data Governance** | Data Governance Lead, Data Stewards (1) | Стандарты Data Contracts, качество данных, каталог |

## Принцип взаимодействия

- Доменные команды владеют своими данными и сервисами, деплоят независимо.
- Платформенные команды предоставляют инфраструктуру и сервисы как продукт доменам.
- Data Governance задаёт стандарты, которым следуют все домены.
